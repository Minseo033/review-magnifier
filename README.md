# 후기돋보기

쇼츠·영상·블로그에 흩어진 제품 사용 경험을 제품별로 모으는 후기 탐색 서비스입니다. 제품을 검색하고 후기를 골라 실제 원문으로 이동합니다.

**서비스:** [후기돋보기](https://minseo033.github.io/review-magnifier/) · **제품 바로 보기:** [퓌 올데이 커버 블랙 쿠션](https://minseo033.github.io/review-magnifier/#product/fwee-all-day-black)

## 현재 공개 범위

공식 제품명과 다른 쿠션 라인을 구분한 **퓌 올데이 커버 블랙 쿠션** 1개, 고유 원문 10개입니다. 쇼츠 4개·일반 영상 2개·블로그 4개를 연결했습니다. 릴스는 검토 가능한 출처를 확보하지 못해 빈 상태로 안내합니다.

- 한글·영문·별칭 제품 검색과 공유 가능한 제품 주소
- 형식·주제·작성자가 밝힌 피부 타입·호수·시간 경과 필터, 작성일 정렬
- 영상 하나만 여는 YouTube 임베드, 자동재생 끔, 재생 제한 시 원문 링크
- 짧은 원문 발췌와 구분된 편집 요약, 후기별 제품 일치·검토 근거
- 제품·후기 저장과 저장함, 저장 제한·오프라인·검색/필터 결과 없음 안내
- 모바일 펼침 필터, 키보드 초점, 본문 바로 가기
- 로컬 운영 도구로 후보 등록·검토 상태 변경·비활성화·링크 점검

직접 구매 문구는 필수 조건이 아니라는 사용자 수정 기준을 적용했습니다. **‘작성자 내돈내산 표기’**와 **‘확인 범위 내 광고 표기 미발견’**을 구분합니다. 광고·협찬·제품 제공·제휴 표시가 발견되면 제외/보류합니다.

초기 목록은 Codex가 공개 텍스트·영상 설명·메타데이터를 검토한 자료입니다. 사람의 영상 시청, 이미지 속 광고 표시나 영수증을 검증한 자료가 아닙니다. 검토하지 못한 범위를 카드와 기준 페이지에 표시합니다. 실제 구매 인증·광고 자동 판정·모든 플랫폼의 실시간 수집은 제공하지 않습니다.

[실제 출처·포함/제외 근거·구현 내용·검증 한계](docs-data/서비스재구성-2026-11-12.md)에 세부 내용을 기록했습니다.

## 실행

Node.js 22 이상과 Python 3을 사용합니다.

```sh
npm ci
npm run build
npm run preview
```

미리보기: `http://127.0.0.1:4187/`. 기존 작업용 서버 `http://127.0.0.1:4190/`도 같은 `docs/`를 제공합니다.

화면은 `index.html`, `discovery.css`, `discovery.js`, 검색·필터·원문 검증은 `discovery-logic.mjs`에서 수정합니다. `npm run build`가 esbuild로 번들을 만들고 공개 파일만 `docs/`로 복사합니다. 별도 API 키, 계정, 데이터베이스 서버가 필요하지 않습니다.

## 데이터와 공개 절차

운영 원장은 `data/discovery-registry.json`입니다. 제품 버전, 원문 URL·게시물 ID, 작성자·날짜·형식, 짧은 인용·요약, 명시된 사용 조건과 근거, 광고 고지 검토 영역, 검토 상태·담당자·날짜, 원문 접근 상태를 기록합니다.

승인 상태이며 활성화되고 필요한 근거가 있는 기록만 `data/discovery.public.json`으로 내보냅니다. 원문을 중복 등록하거나 승인 내용이 변경되면 빌드가 실패합니다. 해시는 변경 감지 수단이며 진위를 인증하지 않습니다. 검토를 하지 않은 채 빌드를 통과시키려고 해시를 갱신하지 마세요.

기존 판매처 원문용 SQLite는 `.local-data/review-magnifier.sqlite3`에 보존합니다. 새 화면은 그 DB나 이전 `catalog.json`을 자동 반영하지 않습니다. 이전 설명과 진입 HTML은 `legacy/`에, 원본 코드·제품 자산은 기존 위치에 남아 있습니다. 원문 전체와 HTML 캐시는 `.local-data/`에만 보관하며 Git과 Pages에서 제외합니다.

저장함은 제품·후기의 ID만 브라우저에 저장합니다. 기기 간 동기화와 회원가입은 없습니다. 기존 v4의 찜·비교 목록을 새 제품의 저장함으로 임의 이전하지 않습니다.

## 후기 추가와 검토

```sh
npm run reviews -- list
npm run reviews -- add /절대경로/후보.json
npm run reviews -- status 후기ID held --reviewer 검토자 --reason "원문 추가 확인 필요"
npm run reviews -- status 후기ID approved --reviewer 검토자 --reason "제품·근거·광고 고지 범위 확인"
npm run reviews -- status 후기ID excluded --reviewer 검토자 --reason "제품 제공 고지 발견"
npm run reviews -- status 후기ID inactive --reviewer 검토자 --reason "원문 변경으로 재확인"
npm run reviews -- check-links 후기ID
```

후보 파일은 원장에 있는 후기와 같은 필드 구조를 사용합니다. `add`는 항상 비공개 후보로 등록합니다. `approved`에는 제품 일치·광고 표기 검토·원문 접근·조건 근거가 필요하며 담당자와 사유를 남깁니다. 피부 정보가 없으면 null로 둡니다. 사용자의 직접 구매 표시가 없으면 `disclosure.kind`를 `not_observed`로 기록하고 확인한 영역과 미확인 영역을 명시합니다.

`check-links`는 YouTube oEmbed 메타데이터와 네이버 본문 접근을 확인합니다. 내용·광고 여부를 재승인하는 명령이 아닙니다. 실패하면 비활성화하고 보류합니다. 릴스는 실제 원문을 수동으로 확인해야 합니다. 변경 사항은 빌드·커밋·배포 후 공개됩니다. 자동 수집이나 서버와 연결된 것처럼 보이는 관리자 화면은 만들지 않았습니다.

## 검증과 배포

```sh
npm run check
npm run build
npm run test:ui
npm run test:data
npm run verify:release
```

UI 테스트는 jsdom의 이벤트·상태·마크업 검사이며 실제 배치·터치·영상 재생 성공을 검증하지 않습니다. 현재 브라우저 연결 오류로 실제 데스크톱/모바일 시각 검수는 미완료입니다. 실제 기기 확인 및 사람이 영상·이미지 고지를 검토하는 작업이 남아 있습니다.

비공개 원문 캐시가 있는 현재 작업 환경에서는 다음 대조도 실행할 수 있습니다.

```sh
npm run verify:sources
```

이 검사는 공개 제목·인용·조건 근거와 원문 캐시, 영상 작성자·날짜·길이·형식 메타데이터, 제외 사유를 대조합니다. 새 체크아웃에는 원문 캐시가 없으므로 실행할 수 없습니다. 일반 빌드·CI는 이 캐시에 의존하지 않습니다. 이전 판매처 자료용 검사는 `npm run verify:legacy-sources`입니다.

GitHub Pages는 기존처럼 `main`의 `docs/`를 게시합니다. 소스와 생성된 공개 파일을 함께 커밋하고 `main`에 푸시하면 Actions가 구문·빌드·UI/데이터 테스트·공개 파일 검증 후 배포합니다. 실패한 배포는 기존 사이트를 대체하지 않습니다. 원문 캐시·개인 DB·제외 후보는 배포 번들에 포함하지 않습니다. `noindex`는 검색 노출 제한이며 접근 권한 제한은 아닙니다.

사진·영상·후기 권리는 각 권리자에게 있습니다. [이미지·원문 출처](ASSET_CREDITS.md)를 참고하세요.
