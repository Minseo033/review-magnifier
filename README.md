# 후기돋보기

제품별로 모은 후기에서 반복되는 장점과 아쉬움을 살펴보고, 요약·원문 발췌·출처를 이어 읽는 팀 프로젝트 시범 서비스입니다.

**사이트:** [minseo033.github.io/review-magnifier](https://minseo033.github.io/review-magnifier/)

## 현재 기능

- 생필품을 포함한 8개 제품군의 실제 제품 20개와 후기 요약 58개
- 제품·브랜드·후기 내용 검색, 카테고리와 정렬
- 첫 화면은 짧은 안내와 추천 키워드에서 바로 제품 목록으로 이어지고, 전체 20개 제품을 고정된 기본순으로 탐색
- 사진 목록 / 후기 중심 목록 전환
- 새로고침해도 유지되는 찜·최대 3개 제품 비교·목록 표시 방식
- 제품별 주소가 있는 후기 상세 페이지, 장점·확인할 점과 원문 출처
- 요약 전용 영역과 문장을 고치지 않은 원문 발췌 58개
- 긍정·아쉬움 주제별 언급 수, 최소 언급 1·2·3개 필터와 근거 후기 목록
- 목록에서도 사양·평점보다 후기 요약을 먼저 강조하고, 상세 화면은 넓은 본문으로 표시
- 데스크톱·모바일 화면
- 검색어와 카테고리 조합, 조건별 해제, 한글 브랜드 검색
- 상세 후기 섹션 이동·제품 링크 복사, 사진/시작 실패 안내
- 브라우저 저장 안내와 자료 수정 요청 이메일

2026년 11월 5~7일 11번가 공개 상품 페이지에서 후기 표본 160개를 확인했습니다. 생필품 8종의 표본 47개를 추가했으며, 제품별 표본 수는 서로 다릅니다. 판매처 전체 리뷰 수, 확인한 표본 수, 화면 요약 수는 구분해 표시합니다. 실시간 갱신·여러 플랫폼 통합·실구매 인증·광고 판별은 아직 연결하지 않았습니다.

기본 정렬은 **고정된 기본순**입니다. 원문·요약·수집 범위는 제품 상세에서 확인할 수 있으며, 광고 자동 판별 기능은 제공하지 않습니다. 검색·카테고리·찜 화면은 해당하는 전체 제품을 보여주며, 다른 정렬 기준을 선택하면 전체 결과에 적용됩니다. 실제 조회수나 품질 순위는 제공하지 않습니다.

제품 상세 주소는 `#product/airpods`처럼 표시됩니다. 해당 주소를 공유하거나 새로고침해도 바로 열립니다. 검색·카테고리·정렬 화면에서 상세로 들어간 뒤 브라우저 뒤로가기를 누르면 보던 조건과 위치로 돌아옵니다.

일반 후기는 요약 문장 대신 짧은 원문 발췌를 표시합니다. 맞춤법·말투와 발췌 구간 안의 줄바꿈은 수정하지 않습니다. 전체 원문은 판매처 페이지로 연결하며, 개별 리뷰 고유 링크가 없어 상품 페이지를 사용합니다.

언급 수는 공개 대상인 원문 160개를 읽고 주제별로 분류한 결과입니다. 같은 후기의 같은 주제는 한 번만 세고, 한 후기는 여러 주제 및 긍정·부정 양쪽에 포함될 수 있습니다. 숫자는 수집 표본 기준이며 판매처 전체 리뷰의 분석이나 긍정·부정 후기 비율이 아닙니다. 별점만으로 분류하지 않으며 기대 표현이나 다른 모델의 고장을 현재 제품의 경험으로 세지 않습니다.

`data/review-annotations.json`에 원문 후기 번호별 분류가 있고, `scripts/prepare-review-insights.py`가 고유 후기 수와 원문 발췌의 일치를 검사해 `data/review-analysis.json`을 만듭니다. 전체 원문과 HTML은 비공개 DB·로컬 캐시에만 유지합니다. 공개된 분석 스냅샷이 있어 원문 캐시 없이도 빌드할 수 있습니다.

추가 생필품은 크리넥스 화장지, 바리바리 키친타월, 베베숲 물티슈, 퍼실 세탁세제, 케라시스 샴푸, 2080 치약 옵션 모음, 크린랲 위생백, JOY 주방세제입니다. 상품 사진과 원문 발췌·요약·주제별 언급 수를 각각 연결했습니다.

## 데이터 저장·수집

2026-11-07부터 로컬 SQLite DB를 사용합니다. 기존 제품 12개·구매 리뷰 원문 113개를 이전했고, 계정 없는 공개 페이지 수집으로 새 판매처 상품 2개·리뷰 원문 2개를 추가했습니다. 생필품을 추가한 현재 DB에는 구매 리뷰 원문 164개가 있으며 160개를 공개 분석 대상으로 검토했습니다. 블로그 후보는 10개(본문 확보 3개)입니다. 신규 후보는 공개 집계에 자동 합치지 않습니다.

DB는 `.local-data/review-magnifier.sqlite3`이며 GitHub에 올리지 않습니다. 빌드는 DB나 로컬 캐시를 자동 반영하지 않습니다. `data/catalog.json`의 후보 중 `data/publication-manifest.json`에서 검토한 내용과 일치하는 제품만 `data/catalog.viewer.json`으로 내보냅니다. 수집과 공개를 분리해 실행 환경에 따라 공개 자료가 바뀌지 않게 합니다. **계정·API 키 없이** `npm run data:products`로 지정 상품의 공개 리뷰 표본, `npm run data:rss`로 지정 블로그의 키워드 일치 글 후보를 저장할 수 있습니다. 기본 대상은 `config/public-sources.json`, 생필품 8종은 `config/household-sources.json`에 있으며 소량 검증·중복 방지·캐시·요청 제한을 적용합니다. RSS 설명은 후기 원문으로 취급하지 않습니다.

선택 사항인 네이버 전체 블로그 검색은 NAVER API HUB 키가 필요합니다. 네이버 쇼핑 상품 검색 API는 2026-07-31 종료돼 실행하지 않습니다. 공개 페이지·RSS 수집도 모든 상품과 전체 리뷰를 보장하지 않습니다.

[저장 구조·공개 페이지/RSS 수집·선택적인 네이버 키 발급](docs-data/저장과수집.md)을 참고하세요. `npm run db:stats`로 실제 저장 건수, `npm run db:doctor`로 설정 상태를 확인합니다.

## 실행 및 수정

Node.js 22 이상과 Python 3을 사용합니다.

```sh
npm ci
npm run build
npm run check
npm run test:ui
npm run verify:release
npm run preview
```

로컬 미리보기는 `http://127.0.0.1:4187/`이며 공개용 `docs/`만 제공합니다. `index.html`, `catalog.css`, `catalog.js`에서 화면과 동작을 수정합니다. `data/catalog.json`에는 검토 전 후보를 포함한 제품 정보가 있고, `data/catalog.viewer.json`이 실제 공개 대상입니다. 수집 원문 캐시가 없어도 저장된 스냅샷으로 빌드할 수 있습니다.

## GitHub Pages 배포

`main` 브랜치의 `/docs` 폴더를 GitHub Pages의 공개 대상으로 사용합니다.

```sh
npm run build
npm run check
npm run test:ui
npm run verify:release
git add index.html catalog.css catalog.js catalog-logic.mjs boot.js review-insights.js catalog.bundle.js package.json scripts tests config/site.json data assets/catalog assets/brand docs docs-data README.md ASSET_CREDITS.md
git commit -m "Update review catalog"
git push
```

`npm run build`는 `docs/`에 배포할 HTML·CSS·JavaScript·제품 사진·공유 이미지·404 페이지와 `.nojekyll`, `robots.txt`를 준비합니다. `config/site.json`에서 공개 주소·문의 이메일·검색 노출 상태를 관리합니다. 사진은 JS에 넣지 않고 같은 사이트의 정적 파일로 제공하며, 사진을 모두 포함한 단일 HTML은 로컬 전달용으로 따로 만듭니다. `main`에 푸시하면 GitHub Pages가 자동으로 다시 배포합니다. Pages에는 이 폴더만 게시하며, 사이트는 별도 로그인 없이 열 수 있습니다. 검색엔진 노출을 줄이기 위한 `noindex`를 넣었지만 비공개 접근제어는 아닙니다.

찜·비교 선택과 표시 방식은 각 브라우저에 저장됩니다. 팀원이나 다른 기기와 공유되지 않습니다. `#privacy`에서 저장 범위를 확인하고 찜·비교를 비울 수 있습니다. 이전 3D 시안, 원문 전체 캐시, 로컬 보고서와 설치 패키지는 저장소에 포함하지 않습니다.

사진·후기 원문의 권리는 각 권리자에게 있습니다. 제품별 출처와 처리 내용은 [ASSET_CREDITS.md](ASSET_CREDITS.md)를 참고하세요.

- 광고 자동 판별 미제공, 한 판매처·한정된 표본의 데모 범위를 홈과 검색에 명시

## 2026-11-09 배포 전 사용성·출처 보강

- 찜 목록 안에서 검색하고, 결과가 없으면 같은 검색어로 전체 제품에서 다시 찾을 수 있습니다.
- 요약의 주제 버튼을 누르면 해당 근거를 펼칩니다. 높은 최소 언급 필터가 켜져 있어도 해당 근거를 볼 수 있습니다.
- 목록의 검색·분류·정렬·표시 방식을 유지하며 상세에서 돌아오고, 이전·다음 제품을 읽을 수 있습니다.
- 찜·비교 삭제와 전체 비우기를 되돌릴 수 있습니다. 저장 제한과 연결 끊김을 화면에 안내합니다.
- 모바일 비교 열 너비와 조작 영역을 보강했습니다. 실제 기기의 화면·스크롤 확인은 별도 필요합니다.
- 출처가 확인되지 않은 추가 54개 제품은 후보 파일에 보존하고 공개 출력에서 제외했습니다. 공개 대상은 로컬 수집 원문과 대조한 20개 제품·160개 후기·58개 요약·58개 발췌입니다.

`data/publication-manifest.json`은 검토한 제품 내용과 공개 이미지의 해시를 고정합니다. 내용·주소·사진이 바뀌면 빌드가 실패하며 새 수집 결과를 자동 승인하지 않습니다. 해시는 변경 감지 수단이며 후기 진위나 실구매를 인증하지 않습니다. 후보를 공개하려면 실제 수집 원문, 상품·후기 번호, 발췌 일치, 요약과 분류 근거, 사진 출처를 검토한 뒤 후보 데이터와 검토 목록을 함께 갱신해야 합니다. 빌드 오류를 피하려고 해시만 다시 생성하지 마세요.

`npm run verify:sources`는 비공개 로컬 수집 캐시가 있는 환경에서 공개 후기의 원문 해시와 발췌를 재대조합니다. 캐시가 없는 체크아웃에서는 이 명령이 실패하며, 일반 빌드와 공개 출력 검사는 캐시 없이 실행할 수 있습니다. DB에서 수정한 내용은 `npm run db:export`로 별도 파일에 내보내 검토합니다. `scripts/expand_catalog.py`, `scripts/add_cosmetics.py`, `scripts/assign_multi_platform.py`는 실제 수집기가 아니며 운영 데이터 준비에 사용하지 않습니다.

검증: `npm run build`, `npm run check`, `npm run test:ui`, `npm run test:data`, `npm run verify:release`. 화면 동작 테스트는 jsdom으로 이벤트·상태·HTML을 확인하며, 실제 브라우저 배치·터치·접근성 인증을 대신하지 않습니다. [작업 결과와 남은 확인](docs-data/배포전-고도화-2026-11-09.md)에 세부 범위를 기록했습니다.
