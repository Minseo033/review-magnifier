# 후기돋보기

제품 사진과 공개 구매 후기 요약을 바로 살펴보는 팀 프로젝트 프로토타입입니다.

**사이트:** [minseo033.github.io/review-magnifier](https://minseo033.github.io/review-magnifier/)

## 현재 기능

- 7개 제품군의 실제 제품 12개와 후기 요약 36개
- 제품·브랜드·후기 내용 검색, 카테고리와 정렬
- 첫 화면에 판매처 리뷰 수 상위 3개를 고정 노출하고, 나머지 9개는 접속할 때마다 랜덤 노출
- 사진 목록 / 후기 중심 목록 전환
- 브라우저에 저장하는 찜, 최대 3개 제품 비교
- 제품별 주소가 있는 후기 상세 페이지, 장점·확인할 점과 원문 출처
- 요약 전용 영역과 문장을 고치지 않은 원문 발췌 36개
- 긍정·아쉬움 주제별 언급 수, 최소 언급 1·2·3개 필터와 근거 후기 목록
- 목록에서도 사양·평점보다 후기 요약을 먼저 강조하고, 상세 화면은 넓은 본문으로 표시
- 데스크톱·모바일 화면

2026년 11월 5일 11번가의 공개 상품 페이지에서 후기 표본 113개를 확인했습니다. 판매처 전체 리뷰 수, 확인한 표본 수, 화면 요약 수는 구분해 표시합니다. 실시간 갱신·여러 플랫폼 통합·실구매 인증·광고 판별은 아직 연결하지 않았습니다.

기본 정렬은 **추천 + 랜덤**입니다. 상위 3개와 일반 목록에는 같은 제품이 중복되지 않습니다. 랜덤 순서는 페이지를 여는 시점에 한 번 정하고 탐색 도중에는 유지합니다. 검색·카테고리·찜 화면은 해당하는 전체 제품을 보여주며, 다른 정렬 기준을 선택하면 전체 결과에 적용됩니다. 실제 조회수는 수집하지 않습니다.

제품 상세 주소는 `#product/airpods`처럼 표시됩니다. 해당 주소를 공유하거나 새로고침해도 바로 열립니다. 검색·카테고리·정렬 화면에서 상세로 들어간 뒤 브라우저 뒤로가기를 누르면 보던 조건과 위치로 돌아옵니다.

일반 후기는 요약 문장 대신 짧은 원문 발췌를 표시합니다. 맞춤법·말투와 발췌 구간 안의 줄바꿈은 수정하지 않습니다. 전체 원문은 판매처 페이지로 연결하며, 개별 리뷰 고유 링크가 없어 상품 페이지를 사용합니다.

언급 수는 저장된 원문 113개를 읽고 주제별로 분류한 결과입니다. 같은 후기의 같은 주제는 한 번만 세고, 한 후기는 여러 주제 및 긍정·부정 양쪽에 포함될 수 있습니다. 숫자는 수집 표본 기준이며 판매처 전체 리뷰의 분석이나 긍정·부정 후기 비율이 아닙니다. 별점만으로 분류하지 않으며 기대 표현이나 다른 모델의 고장을 현재 제품의 경험으로 세지 않습니다.

`data/review-annotations.json`에 원문 후기 번호별 분류가 있고, `scripts/prepare-review-insights.py`가 고유 후기 수와 원문 발췌의 일치를 검사해 `data/review-analysis.json`을 만듭니다. 전체 원문과 HTML은 로컬 `.cache/`에만 유지합니다. 공개된 분석 스냅샷이 있어 원문 캐시 없이도 빌드할 수 있습니다.

## 데이터 저장·수집

2026-11-07부터 로컬 SQLite DB를 사용합니다. 기존 제품 12개·구매 리뷰 원문 113개를 이전했고, 계정 없는 공개 페이지 수집으로 새 판매처 상품 2개·리뷰 원문 2개를 추가했습니다. 현재 구매 리뷰 원문은 115개, 블로그 후보는 10개(본문 확보 3개)입니다. 신규 후보는 공개 집계에 자동 합치지 않습니다.

DB는 `.local-data/review-magnifier.sqlite3`이며 GitHub에 올리지 않습니다. DB가 있는 환경의 빌드는 검토된 자료를 DB에서 내보내 사용하고, 없는 환경에서는 공개 JSON 스냅샷을 사용합니다. **계정·API 키 없이** `npm run data:products`로 지정 상품의 공개 리뷰 표본, `npm run data:rss`로 지정 블로그의 키워드 일치 글 후보를 저장할 수 있습니다. 대상은 `config/public-sources.json`에 있으며 소량 검증·중복 방지·캐시·요청 제한을 적용합니다. RSS 설명은 후기 원문으로 취급하지 않습니다.

선택 사항인 네이버 전체 블로그 검색은 NAVER API HUB 키가 필요합니다. 네이버 쇼핑 상품 검색 API는 2026-07-31 종료돼 실행하지 않습니다. 공개 페이지·RSS 수집도 모든 상품과 전체 리뷰를 보장하지 않습니다.

[저장 구조·공개 페이지/RSS 수집·선택적인 네이버 키 발급](docs-data/저장과수집.md)을 참고하세요. `npm run db:stats`로 실제 저장 건수, `npm run db:doctor`로 설정 상태를 확인합니다.

## 실행 및 수정

Node.js 22 이상과 Python 3을 사용합니다.

```sh
npm ci
npm run build
npm run check
npm run preview
```

로컬 미리보기는 `http://127.0.0.1:4187/`이며 공개용 `docs/`만 제공합니다. `index.html`, `catalog.css`, `catalog.js`에서 화면과 동작을 수정합니다. `data/catalog.json`에는 공개 제품 정보와 재구성 요약·원문 출처가 있습니다. 수집 원문 캐시가 없어도 저장된 스냅샷으로 빌드할 수 있습니다.

## GitHub Pages 배포

`main` 브랜치의 `/docs` 폴더를 GitHub Pages의 공개 대상으로 사용합니다.

```sh
npm run build
npm run check
git add index.html catalog.css catalog.js review-insights.js catalog.bundle.js scripts data assets/catalog docs
git commit -m "Update review catalog"
git push
```

`npm run build`는 `docs/`에 배포할 HTML·CSS·JavaScript와 `.nojekyll`, `robots.txt`를 준비합니다. `main`에 푸시하면 GitHub Pages가 자동으로 다시 배포합니다. Pages에는 이 폴더만 게시하며, 사이트는 별도 로그인 없이 열 수 있습니다. 검색엔진 노출을 줄이기 위한 `noindex`를 넣었지만 비공개 접근제어는 아닙니다.

찜은 각 브라우저에 저장됩니다. 팀원끼리 찜 목록이 공유되지는 않습니다. 이전 3D 시안, 원문 전체 캐시, 로컬 보고서와 설치 패키지는 저장소에 포함하지 않습니다.

사진·후기 원문의 권리는 각 권리자에게 있습니다. 제품별 출처와 처리 내용은 [ASSET_CREDITS.md](ASSET_CREDITS.md)를 참고하세요.
