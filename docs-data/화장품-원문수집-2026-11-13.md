## 검토와 공개 정책

사용자가 최초 프롬프트를 기준으로 재강조했으므로 ‘직접 구매 문구가 없어도 광고 고지가 없으면 허용’했던 중간 기준을 폐기했다. 공개에는 작성자의 직접 구매 문장·위치, 정확한 제품·버전, 상충하는 광고·협찬·제공·체험단·제휴·환급·보상 고지 없음과 사람의 원문 확인·공개 승인이 모두 필요하다. 내돈내산 표시와 수수료 고지가 함께 있으면 제외한다.

네이버 블로그 리서치 스킬의 `naver_search.py`와 `naver_read.py`를 사용해 소량 검색하고 본문 전체를 읽었다. 본문과 링크 목적지 문자열을 대조했으며 쿠팡 파트너스·올영 큐레이터·BrandConnect affiliates 고지를 가진 글을 제외/보류했다. 외부 글에 대한 자동 키워드 매칭만으로 승인하지 않았다. 별도 제외·보류 25개 노트를 `data/discovery-findings.json`에 남겼다. 모두 각각 다른 확정 제외 건수라는 뜻은 아니다.

이미지 속 문구·영상 장면과 음성·연결된 외부 페이지의 추가 고지는 아직 사람 검토가 필요하다. 서브에이전트나 AI 텍스트 검토를 사람 승인으로 기록하지 않았다. 영수증·결제내역 인증은 하지 않았다. 같은 이름의 향 개선·리뉴얼 버전과 개인 선물 후 직접 재구매 기록은 원문 범위를 구분해 승인해야 한다.

신규 쇼츠와 릴스는 직접 구매 표시·정확한 버전·접근 가능한 원문을 함께 확인하지 못해 공개 후보를 억지로 만들지 않았다. 제품이 불명확한 쇼츠 및 유료광고·제휴 영상은 보류/제외 노트에 있다. 기존 퓌 쇼츠 4개·일반 영상 1개는 직접 구매 표기 후보로 유지하고 재승인 대기한다.

## 저장·승인·확장

`data/discovery-registry.json`이 운영 원장이다. 새 제품은 `catalogGroup: beauty`로 분류했다. 전자기기·생활용품은 후속 영역으로 열어두고 현재 수집·공개 데이터에는 섞지 않았다. 메타데이터·짧은 근거만 Git 대상이며 전체 본문·HTML은 `.local-data/rebuild/`에 둔다.

`npm run reviews:queue`는 사진·원문 링크·구매 문장과 위치·확인 범위·미확인 영역을 한 화면에서 볼 수 있는 비공개 로컬 검토 목록을 만든다. 실행 결과는 `.local-data/review-queue/index.html`이며 현재 미리보기는 http://127.0.0.1:4189/ 이다. 이 목록은 승인 버튼이나 가짜 수집 기능이 아니다.

원문을 직접 확인한 운영자가 `npm run reviews -- status 후기ID approved --reviewer 이름 --reason "원문·구매 표시·고지·제품 확인" --human-confirmed`로 승인해야 공개 빌드에 포함된다. `--human-confirmed`가 없거나 직접 구매 근거가 없으면 승인하지 않는다. AI 검토 결과를 단지 플래그만 바꿔 사람 승인처럼 처리하지 않는다.

이번 결과는 별도 작업 브랜치에서 준비한다. 사람 승인 전이라 live 사이트에 빈 목록을 배포하거나 후보를 공개하지 않았다. 로컬 빌드는 사람 승인 자료가 없어 0개를 내보내는 것이 정상이며, UI 테스트의 임시 승인 데이터는 메모리에만 만들고 실제 원장·공개 파일에 쓰지 않는다.
